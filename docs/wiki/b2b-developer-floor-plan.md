# B2B: анализ планировки застройщика

Обновлено: 2026-07-27.

## Назначение

Менеджер загружает изображение плана квартиры, получает черновик структуры
помещений и вручную проверяет его до запуска визуализаций. Автоматическое
распознавание не считается источником истины: размеры, типы, окна и геометрия
всегда доступны для корректировки.

## Границы первого этапа

Реализованы:

- создание B2B-проекта типа `DEVELOPER_FLOOR_PLAN`;
- загрузка JPG, PNG или WebP до 10 МБ;
- фоновый анализ плана через OpenAI Responses API;
- распознавание комнат, нормализованных полигонов, размеров, площади, типа,
  окон и дверей;
- сохранение confidence, заметок и предупреждений распознавания;
- ручное добавление, исключение и удаление комнат;
- ручная корректировка точек полигона, размеров, типа и названия;
- отдельный `styleOverride` для каждой комнаты;
- ручное добавление и редактирование окон и дверей;
- атомарное сохранение пачки комнат с optimistic locking;
- подтверждение проверенной структуры квартиры.

Не входят в первый этап:

- PDF-планы;
- построение пустой 3D-геометрии комнаты;
- итоговая генерация интерьера;
- автоматический подбор товаров для комнат;
- ZIP-экспорт.

Эти функции добавляются следующим этапом поверх подтверждённых `B2BRoom`.

## Поток данных

1. `POST /manager/b2b-projects` создаёт проект с
   `type=DEVELOPER_FLOOR_PLAN` и `sourcePlanFileId`. API принимает только
   загруженный текущим менеджером raster-файл и само получает его URL и
   storage key.
2. `POST /manager/b2b-projects/:id/analyze-floor-plan` атомарно переводит
   проект в `ANALYZING`, создаёт `FloorPlanAnalysisRun` и ставит BullMQ job.
3. Worker читает изображение из S3-совместимого storage по сохранённому key,
   проверяет MIME и размер во время чтения, применяет EXIF rotation и уменьшает
   большую сторону до 2400 px. Произвольные внешние URL не загружаются.
4. `FloorPlanAnalyzerService` вызывает общий `ReasoningAiService` со строгой
   JSON Schema.
5. Ответ отдельно валидируется на стороне приложения. Некорректные полигоны,
   openings и дубликаты не попадают в рабочий набор.
6. Комнаты и openings сохраняются одной транзакцией. Проект переходит в
   `REVIEW_REQUIRED`, а `roomsRevision` увеличивается.
7. Менеджер отправляет исправленный полный набор через
   `PUT /manager/b2b-projects/:id/rooms`.
8. `POST /manager/b2b-projects/:id/rooms/confirm` принимает текущий
   `roomsRevision`, атомарно блокирует эту ревизию, проверяет включённые
   комнаты и переводит проект в `READY_TO_GENERATE`.

## Reasoning AI

Интеграция с моделью изолирована в `ReasoningAiModule` и не содержит
B2B-специфичной логики. Новый сценарий может переиспользовать
`generateStructured()` с другим prompt и JSON Schema.

Переменные окружения worker:

```dotenv
OPENAI_API_KEY=
REASONING_AI_MODEL=gpt-5.6-luna
REASONING_AI_REASONING_EFFORT=low
REASONING_AI_TIMEOUT_MS=60000
```

Провайдер использует `store: false`, timeout, один повтор временной ошибки и
не записывает тело ответа или API-ключ в пользовательские ошибки. Модель
конфигурируется без изменений кода.

## Геометрия

- `polygon` хранится как массив нормализованных точек `{x, y}` в диапазоне
  `[0, 1]` относительно исходного изображения.
- Минимум — три различные точки.
- Полигон должен иметь ненулевую площадь и не пересекать сам себя.
- `wallSegmentIndex` openings указывает на ребро от точки с этим индексом к
  следующей точке полигона.
- `positionRatio` задаёт положение окна или двери на ребре от `0` до `1`.
- Физические размеры хранятся в сантиметрах, площадь — в квадратных метрах.
- Геометрия является проверяемым черновиком для будущего первого этапа
  генерации, а не гарантированной CAD-моделью.

## Состояния и повторные запуски

- `DRAFT` — анализ ещё не запускался.
- `ANALYZING` — активен `FloorPlanAnalysisRun`.
- `REVIEW_REQUIRED` — комнаты распознаны и редактируются менеджером.
- `READY_TO_GENERATE` — комнаты подтверждены.
- `FAILED` — анализ завершился безопасной ошибкой и может быть перезапущен.

Повторный анализ полностью заменяет предыдущий распознанный набор комнат.
Частичный unique index разрешает только один `PENDING`/`PROCESSING` run на
проект; до исчерпания queue retry run остаётся активным.
Сохранение из устаревшей вкладки отклоняется при несовпадении
`roomsRevision`.

## API

- `POST /manager/b2b-projects/:id/analyze-floor-plan`
- `GET /manager/b2b-projects/:id/analysis`
- `PUT /manager/b2b-projects/:id/rooms`
- `POST /manager/b2b-projects/:id/rooms/confirm`

Все endpoints защищены `JwtAuthGuard` и `ManagerGuard`.
