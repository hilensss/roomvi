# B2B manager workspace

Обновлено: 2026-07-19.

## Назначение

Внутренний интерфейс `/manager/projects` нужен для партнёрских визуализаций, которые менеджеры Roomvi готовят от имени мебельных компаний и застройщиков. Marketplace остаётся отдельным пользовательским сценарием.

## Реализованный сценарий: мебельная линейка

1. Менеджер или администратор создаёт проект и выбирает партнёра, одного поставщика, комнату, стиль и необязательный комментарий.
2. Менеджер вручную выбирает от 1 до 6 товаров в каталоге поставщика.
3. API принимает только активные, доступные в наличии, AI-eligible товары с изображениями и сохраняет их порядок и snapshots.
4. Перед запуском API повторяет проверку по актуальному каталогу.
5. Создаётся generation job со сценарием `B2B_FURNITURE_LINE` и двумя запрошенными вариантами.
6. Worker пропускает автоматический product matching и передаёт один и тот же набор товаров в обе генерации.
7. Worker принимает ровно один результат на каждый из двух подготовленных запросов; пустой или лишний ответ провайдера завершает job ошибкой вместо частичного результата.
8. Экран проекта опрашивает последний job, показывает прогресс, две готовые визуализации, исторический состав товаров из snapshots и отдельное скачивание через защищённый потоковый attachment endpoint с allowlist origin, timeout и лимитом размера.
9. После ошибки менеджер может повторить генерацию с сохранённой подборкой; перед повтором API снова проверяет товары.

## Модульные границы

- `B2BProject` и `B2BProjectProduct` хранят партнёрский workflow и ручной набор.
- `RoomProject`, `GenerationJob`, provider adapters, prompts, BullMQ и `DesignVariant` остаются общей генерационной инфраструктурой.
- `GenerationScenario.MARKETPLACE` сохраняет прежний автоматический подбор.
- `GenerationScenario.B2B_FURNITURE_LINE` меняет только способ получения product set и число вариантов.
- Доступ к B2B API контролирует `ManagerGuard`; `MANAGER` и `ADMIN` разрешены, `USER` запрещён.
- B2B `RoomProject`, jobs и design variants исключены из Marketplace API, профиля, выбора пользовательского дизайна и корзины.

## Инварианты

- В проекте ровно один поставщик.
- В сохранённой подборке 1–6 уникальных товаров.
- Все товары активны, `isAiEligible = true`, `IN_STOCK`, имеют хотя бы одно изображение и принадлежат поставщику проекта.
- Генерация мебельщика создаёт ровно две версии.
- Набор товаров не заменяется автоматически и одинаков для обеих версий.
- Редактирование, замена подборки и запуск сериализованы сменой статуса: генерация всегда читает подборку после атомарного захвата проекта.
- Проект нельзя менять во время генерации или после успешного завершения.
- Статус `FAILED` допускает повторный запуск и новую серверную валидацию.

## Следующий этап: застройщики

Планируемый отдельный сценарий принимает планировку квартиры, автоматически выделяет комнаты и создаёт по одной визуализации спальни, гостиной, кухни, санузла и других обнаруженных помещений. У каждой визуализации сохраняется товарная подборка по модели Marketplace. Итоговый экспорт должен формировать ZIP с изображениями и файлами подборок.
